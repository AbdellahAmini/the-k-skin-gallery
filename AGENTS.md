# Prototype Instructions

Run the local server yourself and open the preview in the browser available to this environment. Do not give the user server-start instructions when you can run it.

Before making substantial visual changes, use the Product Design plugin's `get-context` skill when the visual source is unclear or no longer matches the current goal. When the user gives durable prototype-specific design feedback, preferences, or decisions, record them in `AGENTS.md`.

When implementing from a selected generated mock, treat that image as the source of truth for layout, component anatomy, density, spacing, color, typography, visible content, and hierarchy.

Build app UI in `src/`. Keep `.openai/hosting.json`, `worker/index.js`, `scripts/prepare-sites-build.mjs`, and `tests/sites-worker.test.mjs` intact so the same local prototype can be handed to Sites. Before a Sites handoff, run `npm run build` and `npm run test:sites`; the build must leave `dist/client/index.html`, `dist/server/index.js`, and `dist/.openai/hosting.json`.

## Durable rebuild decisions

- Keep the existing Gallery logo, warm ivory and blush palette, editorial serif headings, and calm cart drawer as the visual foundation.
- Checkout is a dedicated `/checkout` route on desktop and mobile. The cart drawer's “Continuer ma commande” action navigates there; do not restore modal checkout as the primary flow.
- Meaningful navigation leads to URL-based pages and product data comes from the backend/catalog, with persisted orders.
- Pre-render customer-facing routes from the public API at build time, then hydrate React Router for in-app navigation; local production preview resolves route HTML and proxies `/api`.
- The surrounding PDF catalogue generator is a separate locked project. Ecommerce changes belong inside `the-k-skin-gallery`.
- Use design galleries to research individual commerce patterns and flows; preserve the Gallery logo, blush/ivory visual identity, and editorial type rather than copying a reference template.
- The primary navigation is Boutique, Marques, Soins, Peau, Routines & Packs, Promotions. The Nouveautés section remains on the homepage. Keep other menu categories, labels, links, and content intact. Soins, Peau, and Routines & Packs use one centered 980px ivory mega-menu frame, consistent editorial headings and 40px+ link targets, soft blush hover states, a restrained page backdrop, and a 200ms fade/drop transition. Adapt the inner layout by menu: three Soins columns plus a blush “À explorer” footer; a 35/65 Type de peau and Besoins layout; and aligned Routines, Packs, and featured Routine columns. Mobile navigation stays in expandable accordions. Discovery and collection filters use the URL and the FastAPI query service. Type de peau and besoin are separate taxonomies; only verified product associations should appear there.
- Packs are sellable entities with component stock accounting. Routines are editorial step pages with deliberately selected products. Merchant content is edited through typed sections; keep structural layout in code.
- Publish all 20 selected Gallery packs with clear French and Moroccan Darija in Arabic letters, selectable on each pack page. Show packs even when sold out; determine availability from the recorded stock of every component. The merchant explicitly chose to count the 94 sample-marked positive-stock products for pack availability. Reserve pack images at `/assets/packs/<pack-slug>.webp`, with a designed placeholder until the image is added.
- Pack detail pages stay compact: show the photo, title, components and morning/evening/weekly guide together near the top. Present component explanations and other advice as short text lists with bullets or numbers, without separate cards or large gaps.
- PostgreSQL is required in production. Apply Alembic migrations before starting FastAPI. SQLite remains available for the local preview and isolated tests.
- Published products remain visible/searchable at zero stock and offer a restock subscription. Publication and inventory states are separate. Import CSV/JSON explicitly with dry-run and safe blank preservation; never invent official facts or live inventory. Manufacturer facts and Gallery curation remain separate, with provenance and human verification. Keep cost and wholesale fields admin-only. Default storefront pagination happens in SQL and the homepage fetches small editorial selections.
- The default boutique includes priced published products whether in stock or not, sorted with available items first; availability filters can show only in-stock or sold-out items. Add a boutique-only "Promotions uniquement" filter. Product cards in a grid keep equal heights and align their purchase/restock action at the bottom. Promotion compare-at prices round upward to the next 10 DH, with a displayed discount between 15% and 25%; preserve each product's customer-facing sale price when adjusting the comparison price.
- Keep the commerce header compact: desktop has a 64px logo/search/actions row, a 38px six-link navigation row, then a 30px blush trust marquee touching the hero. Mobile has a 54px hamburger/logo/search/cart row and a 28px ticker. The full header is sticky in the page flow, including the continuously looping blush trust bar, so it moves naturally at the top and stays visible while scrolling. Center the desktop search field and six-link navigation on the same axis. Keep the logo small with visible space above and below, and preserve the Gallery colors.
- Primary navigation has six routes. Marques, Soins, Peau, and Routines & Packs have small chevrons and content-specific compact dropdowns; Boutique and Promotions navigate directly. The label remains a clickable route, while the chevron is a keyboard-accessible menu control. Desktop dropdowns use short hover intent and a reusable shell; sibling menus switch promptly. Dropdown headings have no numbers. The Marques dropdown shows at most nine active brands in restrained outlined boxes, prioritized by configured homepage featured brands and then product count, sorted alphabetically for display. It has no body heading or popular-brands section; “Toutes les marques” stays in the top-right header and opens the full directory. Mobile shows the same nine-brand preview in its drawer accordion.
- Desktop homepage order after the hero stays Nos marques coréennes, Entrez dans la Gallery, Promotions, Nouveautés dans la Gallery, then Routines & Packs; desktop layout remains unchanged by mobile refinements. Mobile has a separate order: brands, three stacked Gallery entry links, mobile-only Nos incontournables curated products, compact Promotions preview, Routines & Packs swipe rail, 2×2 service reassurance, then footer. Keep the mobile hero compact with small-viewport height units so part of Brands appears sooner; desktop hero sizing and imagery stay unchanged. GalleryEntry is a compact single-column list, not a carousel, and has no artificial see-all link. Keep Routines & Packs horizontally scrollable, with a dynamic swipe hint and tappable position indicators. Hide the novelty section on mobile; do not add the skin chooser. Use one reusable homepage section heading system. Mobile brand logos move in a continuous, softly masked marquee; product grids remain two columns and never span the final odd item. Limit mobile product previews to four, keep product actions aligned, keep footer content above the fixed bottom navigation, and prevent document-level horizontal overflow. Promotions use up to ten genuinely discounted products in a five-column desktop grid; when no offer is published, show a restrained empty state.
- The mobile hero uses one authoritative breakpoint at 760px and a full-bleed photo with an individual focal point per slide. Keep the copy inside the compact lower-left Gallery Placard (max 260px, translucent ivory, rose left rule); retain the desktop composition and desktop focal variable. Mobile hero height is clamp(420px, 56svh, 480px), the CTA is full width inside the placard, secondary navigation is a text link, and indicators are centered Gallery Rose dots/pill above the hero edge. Preserve horizontal swipe and four-second autoplay, and honor reduced motion. Do not add global/mobile hero overrides after the mobile media block.
- Routine steps sit side by side on desktop and remain browsable horizontally on mobile. Present free-shipping thresholds in the cart progress and delivery information instead of a large homepage banner; the cart opens after an item is added.
- Section reveals use a pronounced but fluid slide-up fade: standard sections move about 82px over 900ms, collection results 44px over 760ms, and checkout/admin groups 30px over 680ms. Stagger only the first five cards in content grids by 80ms per item to keep dense collections light. Start observation as content approaches the viewport; render anything already visible immediately. Keep product cards grouped under their section reveal, and never transform the collection-layout ancestor of the mobile full-screen filter. Reduced-motion changes take effect during the session, and cleanup waits for parent and staggered card animations, with a safety timeout. All observer, mutation, animation, and frame work is cleaned up on route changes. The cart drawer and cart page both offer a clear action to empty the entire cart. Use the supplied promo-tag icon in the Promotions page heading and the boutique promo filter.
- On mobile collection pages, filter choices are staged inside the full-screen panel and committed together by “Afficher les résultats”; closing the panel discards pending choices. The Nouveautés collection and homepage novelty section exclude products with a real compare-at promotion, while those products remain available in Promotions and the rest of the boutique.
- In the mobile filter panel, show the number of active filters and a live count of matching products before confirmation. Keep the all-filters reset action in the sticky panel header. Filter sections start collapsed, show their active count when collapsed, and each active section has its own small reset control. Activating the boutique promotion filter applies immediately and closes the panel; deselecting it keeps the panel open so other filters can be chosen. Keep the mobile navigation bar fixed to the viewport bottom outside the page shell.
- Product catalogue facets allow multiple choices within each section. Values inside a section combine with OR; different sections combine with AND. Facet counts are calculated after applying selections from the other sections, so each number shows the products that choice would add under the current cross-section filters.
- The boutique search stays compact behind a magnifying-glass button, expands on activation, filters the product list through the URL query, and collapses when cleared or dismissed empty.
- Keep the homepage brand strip editorial and understated: a quiet ivory background, clear logos, and no gradient or individual pill frames. The trust ticker moves right while the brand logos move left, both at the same measured pixel speed on desktop and mobile.
- The pack directory uses boutique-style URL filters and multi-select counts over trustworthy pack data: component category and brand, pack skin suitability, availability, and price. The Routines & Packs directory previews four available pack cards and keeps “Voir tous les packs” inline with the Packs heading, aligned at the trailing edge. See-all links use the Gallery rose color and a right arrow. The Promotions navigation label stays in the normal text color and carries a rose promo-tag icon. Product pages surface the available pack with the largest verified saving against buying every component at its current unit price, with a link to other packs containing that product.
- In admin, pack creation and editing use an overlay editor. Remove the inline editor below the pack table; clicking outside closes a clean editor, while unsaved changes require an explicit save, continue, or discard choice.
